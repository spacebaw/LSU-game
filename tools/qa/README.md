# tools/qa: repeatable QA harness (real Chrome, no dependencies)

Node 24 plus the Chrome harness in `test/browser.mjs`. Every script launches its own headless Chrome, prints a short summary and exits non-zero on a problem. Screenshots and other output go to `tools/qa/out/` (git-ignored).

- `node tools/qa/play.mjs [--size 96|64] [--only a,b] [--out dir] [--shots] [--index path] [--strict] [--list]`: scripted play-through, one summary line per scenario and size (default both sizes). Scenarios: `tutorial`, `network-hold`, `land-office`, `dredge`, `hurricane`, `night-game`, `year-rollover`, `save-load`, `hud-modes`, `zoom-steps`, `build-tabs`, `issues-tray`, `title-panels`. Fails on any console error, uncaught exception, `BSU.error` or failed check (`--strict`: console warnings too). `--shots` saves a PNG per scenario (and at key moments) as `<size>-<scenario>-<label>.png`.
- `node tools/qa/fps.mjs [--size 96|64] [--dpr 2] [--zoom 1] [--night] [--index path] [--frames 150] [--runs 1] [--width 1440] [--height 900] [--buildings 46] [--pan] [--paused] [--shot name]`: frame profiler on a dense campus (about 46 placements, i.e. ~38 buildings and 8 plants, through `BSU.headless`, viewport fully on the map, 150 rAF frames after the HD bake). Prints `frameMsMean`, `fps`, draw calls, chunks, agents, `memMB`, the terrain-cache hit rate and rebuilds (`tcacheHitPct`, `tcacheBuilds`) and the chunk bakes during the sample (`chunkBakesM1`, `chunkBakesM2`: both should be near 0 at rest; when they differ between A and B the frames are not comparable) and the `passMs` table. `--night` runs a lit Stadium II night game instead of a day frame. `--paused` (water pass) stops the sim before sampling, so every frame draws the same campus and only the render code differs between two builds: with the sim running the frame time follows what the students are doing in the sampled frames (a walking crowd bakes and draws more sprite frames than a standing one), and two builds whose campuses have drifted apart can differ by 15 % for that reason alone. `--pan` then pans 20 tiles toward the map centre and samples again (the ring must pre-bake and the view upgrade again; the resting sample must show 0 bakes).
- `node tools/qa/fps.mjs --compare pathA pathB [flags]`: runs both pages (interleaved with `--runs N`) and prints A, B, B - A and the percentage per row.
- `node tools/qa/campaign.mjs [--index path] [--size 96|64|both] [--seed 1] [--seeds N] [--years 15] [--policy goals|greedy|passive|storm|all] [--jobs K] [--assert] [--json out.json] [--tune a.b=1,...] [--diag] [--quiet]`: **headless (Node, no Chrome)** campaign runner for balance and pacing. Plays a skipTutorial game one in-game day at a time under a named policy that acts only through `BSU.headless` and the module APIs the UI calls (`buildings.place/placeRun/upgrade/linkBuilding/repairAll/boardUp/retrofitPilings`, `economy.set*`, `sports.hire*`, `land.buy`, `headless.fill`): `goals` does what the coach's card, the Issues tray and the HUD needs strip say (the way a new player would); `greedy` maxes students as fast as cash and the loan line allow and buys prestige once it is applicant-bound; `passive` builds the tutorial minimum and hoards; `storm` is greedy plus the cove levee, a ring at 8 ft, pumps, generators, pilings, insurance, board-up and sandbags before every storm. Prints a year-by-year table per run (cash, income, expense, students, applicants, the capacity terms, prestige and its target, happiness, ecology, the football record, sections, buildings, milestones, flooded and unrepaired halls, storms, the goal on the card) and medians / worst cases over the seeds; `--assert` exits non-zero when the pacing bands are missed on the median (see `BANDS` in the file); `--index` plays another build (a before / after pair: `--index tools/qa/out/index-before.html`); `--tune` patches `BSU.params` before the game for experiments; `--diag` prints an end-of-run diagnosis (what is flooded and why, the ring, the prestige / happiness / ecology terms). Runs fan out over child processes (`--jobs`, default min(4, cpus − 1)); a 15-year run takes 4–12 minutes depending on the campus. docs/BALANCE_NOTES.md records what it found.
- `node tools/qa/shots.mjs [--size 96|64] [--dpr 1] [--only title,day,hud,zoom,night,weather,hurricane] [--out dir] [--index path] [--prefix x-] [--scale 1|1.15|1.3]`: screenshot matrix with stable names: `title howto about`, `day-1280x800 day-1440x900 day-1920x1080`, `hud-full hud-hidden`, `zoom-0.5 zoom-2.5`, `night-lights night-game`, `fog rain hurricane`.
- `node tools/qa/contrast_audit.mjs [--width 1440] [--height 900] [--size 96|64] [--scale 1|1.15|1.3] [--only state,…] [--verbose]`: **UI refresh U6** WCAG audit of the live DOM: 37 states (title, the dimmed title under the sheet, at rest, goal card, the goal card's steps (folded and short: goal steps pass), every popover, Menu list / Budget / Settings, Build sheet collapsed / expanded with a greyed card, Alerts rows of every severity, a dialog, the coach, inspect card / pill, the inspect card's upgrade block (locked with its reason, open and lit, under way) and Season with the Night games switch lit (goal steps pass), the Board's chip in its three tones with the deficit / deadline / receivership / exit dialogs, a refusal snackbar with "Why?" and the goal card's paused row and pill (unstick pass), snackbars, night, storm, hidden HUD); every visible text node, `svg.ic` icon and control border is checked against its effective background (ancestors up to the first opaque / ≥ 94 % surface, translucent layers and the dialog scrim composited, a floating surface composited over the world-canvas pixel beneath it). Text ≥ 4.5 (≥ 24 px or bold ≥ 19 px: 3.0), icons / borders ≥ 3.0; inactive content (disabled / locked, under a cover, the inert dimmed title) and an element caught in the middle of an opacity animation or transition (a fading cash delta: water pass) is reported as info. Prints the states × checked × failing table, writes `out/u6-contrast.txt`, exits 1 on a failure.

- `node tools/qa/roads_scene.mjs [--index path] [--tag after] [--out dir] [--dpr 1] [--pen]`: the roads-and-paths scene on seed 42 at 96 (a road L-turn, a 4-way cross, a road T, a path T into a road, a path crossing a road, a 1-step staircase of each kind, a road dragged over a bayou with marsh banks) laid through `buildings.placeRun` on the flattest chartered block, shot as `roads-<tag>-z1`, `-z2-cross`, `-z2-tees`, `-z2-stairs`, `-z2-bayou` and a mid-drag `-ghost`; `--pen` adds the pen stroke path (`sprites.isHD` patched false). Run it on `tools/qa/out/index-before.html` (a copy of the previous build) and on `index.html` for a before / after pair.

`--index path` (play, fps, shots) runs another copy of the game. A/B against HEAD, from this folder: `(cd .. && git show HEAD:bayou-state/index.html) > /tmp/x.html && node tools/qa/fps.mjs --compare /tmp/x.html index.html`. Paths are resolved from the current directory.

Headless Chrome here is software raster (`--disable-gpu`) and `deviceScaleFactor` is fixed at 1; dpr 2 is emulated by redefining `window.devicePixelRatio` and firing a resize. Timings are only meaningful as before / after deltas on the same machine in the same minute: use `--compare` (and `--runs 3` when the delta is small), never compare absolute numbers across machines or against a GPU browser. `passMs` blames the pass that flushes the raster, not the one that costs, so read it as A/B too. Keep other heavy processes off the machine while a run is going: a loaded CPU stalls the game loop and shows up as flaky scenarios.

Kill stray headless Chromes after an aborted run (the scripts do it on a normal exit):

    pkill -f 'user-data-dir=.*bsu-chrome-'

Layout: `lib.mjs` (shared helpers: `openGame`, `g.key`, `g.place`, `g.waitBake`, `g.shot`, `g.sample`, `g.buildCampus`, `g.frameCampus`, ...), `play.mjs`, `fps.mjs`, `shots.mjs`, `contrast_audit.mjs`, `u6_matrix.mjs`, the `u2_scene … u5_scene` scripts, `roads_scene.mjs`, `goal_scene.mjs`, `crossings_scene.mjs`, `steps_scene.mjs`, `unstick_scene.mjs`, `water_scene.mjs`, `life_scene.mjs` (+ `life_campus.mjs`), `colleges_scene.mjs`. Set `QA_TRACE=1` to log every page evaluation slower than 2.5 s. Each page evaluation has a 60 s timeout (the stuck page's stack is printed), so a page stuck in a loop fails the check instead of hanging the run.
- `skip_scene.mjs [--strict] [--index …]`: clicks the real Skip button during a full game (before and after kickoff), a paused parade, a near miss, a Spring Game and a graduation; each must end on one click.
